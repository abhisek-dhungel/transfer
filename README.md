# TechSastra Send

**Send files. Simply.**

A modern, production‑ready file‑transfer web app built with Next.js, TypeScript, Tailwind CSS, MySQL (Prisma), Cloudinary and Resend. Users can upload a single file (≤ 100 MB) and send a secure download link to a recipient’s email – no account or login required.

## Features
- One‑click file upload directly from the browser to Cloudinary (no Vercel payload).  
- Secure, cryptographically random download token (`/download/[token]`).
- Email sent via **Resend** from `transfer@techsastra.com` with a responsive HTML template.
- 7‑day automatic expiration; expired links are invalid.
- IP‑based rate limiting (default 5 transfers per hour).
- Fully responsive, WCAG‑compliant UI with subtle animations.
- Deploys on Vercel (serverless, no persistent filesystem).

## Database & Prisma
1. **Create a MySQL database** (e.g., on PlanetScale, Azure Database for MySQL, etc.).
2. Set `DATABASE_URL` in `.env.local`:
```
DATABASE_URL="mysql://USER:PASSWORD@HOST:3306/DATABASE_NAME"
```
3. Run Prisma migrations:
```bash
npx prisma generate   # generate client
npx prisma migrate dev --name init   # creates the Transfer table
```
   - In production you will run `npx prisma migrate deploy` (Vercel).  
4. The `Transfer` model (see `prisma/schema.prisma`) includes indexes on `token`, `recipientEmail` and `expiresAt` for fast look‑ups.

## Cloudinary Configuration
1. Sign up / log in to Cloudinary.
2. **Create an upload preset** (unsigned or signed – the code uses signed uploads). Note the preset name; put it into `CLOUDINARY_UPLOAD_PRESET`.
3. Add the following env vars:
```
CLOUDINARY_CLOUD_NAME=your-cloud-name
CLOUDINARY_API_KEY=your-api-key
CLOUDINARY_API_SECRET=your-api-secret
CLOUDINARY_UPLOAD_PRESET=your-preset
```
4. The app uses `resource_type: 'auto'` so any file type listed in the UI is accepted.
5. **Security:** API secret lives only on the server (`lib/cloudinary.ts`). No secret is exposed to the browser.

---

## Resend Setup
1. Sign up at https://resend.com and create an API key.
2. Add a **verified sending domain** `techsastra.com`.
   - Follow Resend’s UI to add DNS records (SPF, DKIM). **Copy the exact values** shown – do **not** hard‑code them.
3. Create the sender address `transfer@techsastra.com` in Resend.
4. Add to `.env.local`:
```
RESEND_API_KEY=your-resend-api-key
EMAIL_FROM=transfer@techsastra.com
```
5. The email template lives in `emails/TransferEmail.tsx` (generated by the code).  
   - It includes a plain‑text fallback and responsive HTML.

## Environment Variables
All required variables are listed in `.env.example`.  
Copy it to `.env.local` and fill in your secrets.  
**Never commit `.env.local`** – it is in `.gitignore`.

| Variable | Description |
|----------|-------------|
| `DATABASE_URL` | MySQL connection string |
| `DIRECT_URL` *(optional)* | Direct URL for Prisma when using serverless providers |
| `CLOUDINARY_CLOUD_NAME` | Cloudinary cloud name |
| `CLOUDINARY_API_KEY` | Cloudinary API key |
| `CLOUDINARY_API_SECRET` | Cloudinary API secret (server‑only) |
| `CLOUDINARY_UPLOAD_PRESET` | Upload preset name |
| `RESEND_API_KEY` | Resend API key |
| `EMAIL_FROM` | Sender address (`transfer@techsastra.com`) |
| `NEXT_PUBLIC_APP_URL` | Public URL of the deployed app (e.g., `https://send.techsastra.com`) |

| `TRANSFER_EXPIRY_DAYS` | How long a link stays valid (default 7) |
| `RATE_LIMIT_MAX` | Max transfers per IP per window |
| `RATE_LIMIT_WINDOW` | Window length in seconds (default 3600) |

## Testing Checklist
- **Upload**: 1 KB, 10 MB, 50 MB, 100 MB – all succeed.
- **Oversize**: 101 MB – rejected with proper UI error.
- **Email**: Check Gmail, Outlook, Yahoo – link appears, clickable.
- **Download**: Valid token works, expired token shows “This transfer has expired”, invalid token shows “Invalid link”.
- **Rate limit**: Exceed 5 transfers from same IP within an hour – error shown.
- **Mobile**: Test on iOS & Android browsers – drag‑and‑drop falls back to file picker.
- **Accessibility**: Keyboard navigation, focus outlines, ARIA labels.
- **Performance**: Verify no large payload passes through Vercel (direct Cloudinary upload).

## Vercel Deployment
1. **Create a new project** on Vercel and connect it to the GitHub repo `abhisek-dhungel/transfer`.
2. **Add Environment Variables** in the Vercel dashboard (Settings → Environment Variables). Use the same values as in your local `.env.local`.
   - Mark the **Production** values accordingly.
3. Vercel will run `npm install && npm run build` automatically.
4. After the first deploy, you’ll get a preview URL (`https://<project>.vercel.app`).
5. **Production Domain** – add a custom domain `send.techsastra.com` (Settings → Domains) and point the DNS CNAME to `cname.vercel-dns.com` as instructed by Vercel.
6. Enable **Automatic Prisma Migrations** via a Vercel Build Step (add script `prisma migrate deploy`). Example in `vercel.json` (optional):
```json
{ "build": { "env": { "DATABASE_URL": "${DATABASE_URL}" } } }
```

## Custom Domain & DNS for `send.techsastra.com`
1. In your DNS provider, create a **CNAME** record:
   - **Name**: `send`
   - **Value**: `cname.vercel-dns.com`
2. Wait for propagation (usually < 5 min).
3. Verify in Vercel → Domains that the status becomes *Connected*.

## Email DNS (SPF/DKIM/DMARC) for `techsastra.com`
Resend requires the sending domain to be verified. After you add `techsastra.com` in Resend:
1. **Copy the exact DNS TXT records** shown in the Resend UI – they include:
   - **SPF** (e.g., `v=spf1 include:resend.com ~all`)
   - **DKIM** (two TXT records named `protection._domainkey.techsastra.com` and `mail._domainkey.techsastra.com` with long keys)
2. Add those records **exactly** to your DNS zone. Do **not** modify the values.
3. (Optional) Add a **DMARC** policy:
```
_dmarc.techsastra.com  TXT  "v=DMARC1; p=none; rua=mailto:postmaster@techsastra.com"
```
   - Adjust `p=` to `quarantine` or `reject` once you’re comfortable.
4. After DNS propagation, Resend will show the domain as **Verified**. Only then can you send from `transfer@techsastra.com`.

## Rate Limiting & Abuse Prevention
- Implemented in `lib/rate-limit.ts` using Upstash Redis (`@upstash/ratelimit`).
- IP‑based limit: **5** transfer attempts per **3600 seconds** (1 hour).  
- Configurable via `RATE_LIMIT_MAX` and `RATE_LIMIT_WINDOW` env vars.  
- The same limiter is used for:
  - `/api/upload/signature`
  - `/api/transfers`
  - `/api/download/[token]`
- If you prefer a different store (e.g., Cloudflare Turnstile later), the code is modular – just replace the limiter implementation.
